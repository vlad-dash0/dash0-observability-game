Prototype notes

  • Same grading: the spans, trace ids and answer come from levels/spans-and-traces.mjs. setParent and checkBuild are copied unchanged. The tick or note after a drop is checkBuild's result for the span you just moved. A span's grade depends only on its own parent, so that per-drop result is exact. The trace counts as assembled when every span is placed and checkBuild passes as a whole.
  • New view behaviour, not new grading: the arrival queue, the time band, the "likely parent" highlight, the tiered hints and the stars are all view-side. Hint 2's second candidate is a decoy picked from the timing: the next-closest span that also contains it, or "No parent (root)".
  • Not verified: nobody has seen this in a browser, on a phone or with a screen reader. Touch drag starts from the grip; tapping uses the pick path. No span in this level is ERROR, so the error marker appears only in the legend.
  • Trace tint is a help on L1 and L2 only: each trace id gets its own tint, and while you move a span, candidates from another trace fade and show "other trace". They still accept the drop, and dropping there gives the note. On L3 and L4 the trace chips are plain.
  • Difficulty tabs are simulated: all four use the 2.1 spans and only switch helps on or off. Switching a tab resets the board. Without instant feedback, Hint picks the span to help with from checkBuild, so pressing it shows which span is still wrong.
